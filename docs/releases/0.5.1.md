# AIDD 0.5.1

This patch fixes the scope of native schema-2 amendment checks without weakening
owner consent, declared file ownership or the final closing gates.

- `rules check --unit <id> --phase build --target <path>` checks the approved
  amendment and its transitive parents instead of requiring historical base
  closing work before implementation can begin.
- `check --unit` and `readiness --unit` select the actual amendment documents and
  project root. Unknown, malformed or escaped selections fail closed. Pending
  preapproval consent is distinct from invalid or stale consent.
- Shared components outside conventional directories can be proved through an
  exact registry entry, a real export, declared screens and production import/JSX
  use. Comments, strings, regular expressions and test-only consumers are excluded.
- Readiness observes the selected package, parents and shared-component proof
  inputs. It does not grant approval or claim runtime verification.

Verification: 155 targeted regression tests passed in one coordinated run on
Python 3.12. The implementation also received an independent source audit.
Wheel and source distributions are built with `python -m build`; package
metadata is checked with `python -m twine check` before upload.

Installed copies are updated with transactional `aidd sync`, preserving backups
and project-local evidence, memory and gate state. No application source or
database migration is part of this release.
