## Evidence from real use (project `b1SycLink`, 27 specs, read 2026-10-05)

- 14 of 27 specs are open with `Approved: PENDING` in tasks.md: `F13-eDoc-Emission-Engine` .. `F24-eDoc-Traceability`, `F26-eDoc-Tax-Catalogs`, `F27-Correction-Backlog`. `F25-eDoc-Approvals` has no tasks.md.
- The R6 code gate (`rule_gate._code_gate`) loops EVERY open spec of the root, so approving the frontend/prototype of one spec left the other 13 blocking every code write. The owner set `AIDD_RULES=warn`; 358 code edits happened with no approval.
- `.aidd/active_spec` is NOT a reliable pointer in real use: `mark_code_edit.py` re-points it on ANY spec file edit. At the time of reading it held `F28-DB-Unification-Sync`, a spec with only `spec.md` (spec_edit events only, not open) while 14 other specs were open. A gate that trusted that pointer would be ambiguous on day one; this is why FR-201 uses its own gate pointer and a deterministic fallback.
- No spec reached Step 6. `check_spec.py` reported "0 gaps" on specs with real runtime defects because it is structural-only (`check_spec_dir(static_only=True)`) and nothing was ever executed.
- Spec ids in the real project are not numeric (`F23-eDoc-POS`): every path-shape guard in the hooks must be tested with such ids, not only with `002-aidd-...`.
- `F13-eDoc-Emission-Engine` alone has 151 headings of level 2-3 across its five reviewable files (spec 11, plan 16, tasks 104, mockup-audit 7, contracts 13) and a 84 KB tasks.md: the review page must stay usable at that size.

## Scope
- **Included:** `aidd review <spec>` (generate `review.html`, check `review.md`), approval through `review.md` PLUS a human consent act, R6 scoped per spec through a gate pointer plus `aidd rules activate`, `## Verification` + `aidd verify` + `verify_run` evidence with a working-tree fingerprint, ONE closing auditor with a result floor, R5 advisory by default (including the legacy graph-coherence hook), R8 scoped with a reminder for the other specs, `## Optimization brief`, `aidd status --refresh`, structural-only banner in `check_spec.py`, `rules_override` visibility for `warn` AND `off`, `code_edit`/`subagent` recorder changes, docs and mirrors.
- **Excluded (decided against, see "Resolution of conflicts"):** `aidd review serve`; a server of any kind; a random nonce handshake; `--write-state` / STATE.md derived region; migration counting; a `park` command; a `.review-state.json` sidecar or `review.prev.md`; R10/R11 re-checks at close; the external skill `aidd-converge` (lives outside the repo, owner updates it).

## Risks and residuals

- **Consent, not the file, is the trust root.** `review.md` is a plain file and the Bash guard is lexical (`python /tmp/forge.py` is not seen), so a forged complete review.md is assumed possible; it mints nothing without a consent act the agent cannot write: a recorded user answer, a hook-recorded user prompt, or an interactive TTY. Residuals: an agent that spawns a pseudo-terminal could feed the TTY route (the typed tag is public); the prompt route trusts that the user typed the tag. The consent act lands in the `approved` event (`source`, `consent_ts`) for the owner to audit.
- **Pointer flipping.** `aidd rules activate` is free (Open decision O-2) and an agent can aim the gate at an approved spec while editing code for another. Compensation: the pointer is separate from the informational one, every change is logged and printed by `aidd status` and the Stop message, each `code_edit` is stamped with the target, and approval of each spec needs its own review. Code edits still do not say which spec they implement beyond that stamp.
- **R8 is per-spec, not global.** Approved specs that are not the target get a once-per-session reminder, not a block; the blocking guarantee of M10 now applies to the target. The reminder reaches the user (`systemMessage`) and the model (SessionStart context line).
- **`aidd verify` runs shell commands from spec.md.** Mitigations: lint (no inline-code interpreters, no self-satisfying `contains:`, must name a runner or a repo path), `verify_hash` bound to the owner's approval, evidence sha1, never run from a hook, timeout per row, zero-test and short-output heuristics, fingerprint of the tree. Same trust as running the project's tests; a malicious-but-lint-clean command remains possible, and tests the agent weakened still pass. The owner sees the table in the mandatory section of the review.
- **Freshness blind spots.** Edits made through Bash/PowerShell, formatters, `git checkout/merge/pull/reset` and `npm install` record no `code_edit`; the working-tree fingerprint covers them when git is available. Outside git the fallback is the max mtime of project files (capped at 20 000 files / 5 s; above that only the `code_edit` rule applies).
- **Bash/PowerShell code edits are not recorded** as `code_edit` (existing limit); see above for the fingerprint.
- **151 checkboxes** on a large spec: mitigated by "check all in file" and "Approve all" (conscious clicks, mandatory sections excluded); renaming a heading orphans its check (forces re-review, orphan comments are listed). A source over 400 000 characters cannot be reviewed on the page (fail closed) and falls back to the answer-only route.
- **Browser:** `Blob` + `<a download>` works from `file://` in Chrome, Edge and Firefox; Safari may open the text instead (documented). The owner moves `review.md` from Downloads into `specs/<id>/` (the agent cannot, by hook). T-11 checks that relative images load under the CSP from `file://`.
- **Hand-written markdown renderer** will not match CommonMark; unsupported constructs degrade to escaped text and the markdown stays the source of truth. It is the main XSS surface: escape-first design, no raw HTML, strict URL allow-list, script CSP by hash, JSON blob escaping and an explicit XSS test list also run in a real browser.
- **Closing-audit marker spoofing.** The marker is still text written by the agent being audited. Hardened by: tags bound to the current tasks/verification hashes, a recorded final report of at least 1500 characters, a qa-audit.md checklist table citing the auditor's `tool_use_id`, R14, the audit window and the post-`verify_run` ordering. It raises the cost of faking; it does not make the auditor independent of the main agent's prompt. If the host's hook payload has no `tool_response`, `result_chars` is absent, the closing auditor never counts and the per-domain route is the fallback (Open decision O-10).
- **R5 advisory** lets planning proceed with no subagent; the human gate that remains is the review approval with consent. `AIDD_R5_AUDIT=strict` is available.
- **`AIDD_RULES=off` cannot be prevented** (owner-level env), only made visible: `rules_override` at SessionStart/Stop and the effective value in `aidd status`.
- **Bootstrap.** This spec is approved under the old gates (no `gate: 2` yet), so it closes through the legacy path; its own Verification table is executed by T-10/T-11 as dogfooding after install.
- **Mirror drift:** `aidd_evidence.py`, `aidd_rules.py`, `aidd_status.py`, `check_spec.py`, new `aidd_review.py` must be byte-identical in `adapters/dot-aidd/scripts/`; `AIDD.md`, `templates/spec.md`, `templates/qa-audit.md`, `templates/review.html` too (a new identity test covers docs/templates, which were not enforced before).
- **Tests that must change** (named in the tasks): tests/test_aidd_rules.py `TestCheckSpecDir` (`test_no_mapper_after_spec_edit`, `test_tasks_chain_and_approval`, `test_graph_rebuilt_needs_subagent_after`) pin `AIDD_R5_AUDIT=strict`; tests/test_rule_gate.py `test_b1_every_open_spec_is_checked_not_just_one`, `test_mdl_abandoning_one_spec_unblocks_the_other_dead_end`, `test_d1_code_gate_never_reads_the_pointer`; tests/test_stop_gate.py `test_two_open_specs_both_count_and_abandoning_one_leaves_the_other` and the `no distinct ... auditor` texts; R5 tests in tests/test_rule_gate.py ~L1850-1900 pin strict; close tests in test_aidd_status.py / test_cli_rules.py keep passing through the legacy path; grep fixtures for the phrase "closing audit" before finalizing (it flips coverage).
