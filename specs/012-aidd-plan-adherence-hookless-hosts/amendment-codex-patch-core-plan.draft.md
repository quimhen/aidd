# Draft plan — Codex patch pre-gate

## Naming & File Contract (fill this first — everything below depends on it)
| Item | Convention |
|---|---|
| Functions / variables / methods | Python snake_case; preserve `decide(event) -> (blocked, message)` |
| Files | `skill/hooks/codex_patch.py`, `skill/hooks/rule_gate.py`, byte-identical matching `adapters/dot-aidd/hooks/` mirrors; stdlib tests only |
| Projection | `project_patch(command: str, cwd: str) -> list[PatchTarget]`; each target carries operation, original and destination path, existing text, prospective text, and an explicit proof or a typed rejection. No writes or hook event fabrication. |

## Contract and order

1. T-23 adds a strict parser and in-memory projection for a bounded native grammar: ASCII patch payload with `*** Begin Patch` and `*** End Patch`; one or more unique `*** Add File: <relative-path>` or `*** Update File: <relative-path>` operations; adds contain only `+` lines; each update has exactly one unlabelled `@@` and only context (` `), removal (`-`) and addition (`+`) lines. An update's existing file must be nonempty ASCII with LF-only lines and a final LF; the non-addition sequence must occur exactly once as complete lines. Add targets must not exist; empty adds produce empty bytes, nonempty adds and updated files have final LF. Reject CRLF, missing final newline, non-ASCII, empty update preimage, fuzzy whitespace matching, duplicate matches/targets, nested operations, labelled/multiple hunks, delete, move, `*** End of File`, binary data, path escapes or any syntax not in this subset. Reject file changes between two reads. Resolve paths via existing canonical rules, and do not follow an escape as a supported target. The subset must be compared against the real native tool in a disposable project; unsupported native variants are refused, not represented as parity.
2. T-24 wires the helper into the **direct `rule_gate.py` entrypoint** for the canonical native tool name. For each path create a target-specific input: for a supported update, use the exact nonempty observed original as `old_string` and exact projection as `new_string`, so `_would_be` and its pre-existing before/after comparison continue to run; for an add, use the exact prospective file as `content`. Reject deletion or move, and any case whose content cannot be proved. Protect `.env`, `spec.md`, `plan.md`, `tasks.md`, `contracts.md`, `qa-audit.md`, `review.md`, and `review.html` with the existing controls; unknown content must never skip `_would_be` or `_env_control_write`.
3. The gate computes every decision without writing, then allows only if all are safe. Preserve tool/session/cwd. Do not mutate events, change the owner approval, write protected files or treat a later post-hook as prevention. Existing tools, hooks, and legacy schemas remain unchanged.
4. A single orchestrated round covers new focused tests plus existing gate and adapter tests; independent security and functional review follows. A scratch-repository real-host test proves pre-block and allowed patch delivery. If actual payload/projection cannot be proven, mark runtime unverified rather than supporting the host by assertion. Do not run two builds concurrently.

The host may change a file between pre-hook and the actual patch; the native tool can apply a fuzzy match after that change. Two reads during projection do not close this race. Do not claim atomic fail-closed protection or production readiness without either verifiable exclusive control spanning validation and write, or a demonstrated pre/post mechanism that detects divergence and prevents continuation, explicitly without promising to undo an already applied effect. Neither mechanism is established here. A scratch race test alone does not prove exclusion. Correcting post-event provenance and reopening remains a later, separately approved phase.

## Pre-approval blocker

Windows native scratch observations (Codex CLI 0.165.0, invoked directly with `--codex-run-as-apply-patch` in temporary directories): exact unique update and ASCII add worked; CRLF was preserved; a missing terminal newline was added; duplicate matches used the first occurrence; whitespace-fuzzy matching was accepted; missing context failed. The contract deliberately rejects CRLF, missing terminal newline, duplicate and fuzzy matches instead of assuming broad native parity. These samples do not prove the subset for all inputs or a real pre-hook delivery; require seeded scratch comparison on Windows and Linux and a real hook smoke run before supporting the host.
