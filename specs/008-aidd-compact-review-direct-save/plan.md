### Exact interfaces (frozen; owners may add private helpers, never rename these)

**Module split (acyclic, so three owners build in parallel in wave 1).** The 007 module `aidd_review.py` stays the ONLY entry point and facade (the CLI, `aidd_status.py`, `rule_gate.py`, the e2e test and `test_rule_gate.make_review` import only `aidd_review`); the new logic lives in two NEW pure modules next to it:

```
aidd_review.py (T-08, facade + IO + CLI)
   |-- lazily --> aidd_review_items.py (T-01, NEW: source markdown -> items, digests, summary data)
   |-- lazily --> aidd_review_state.py (T-07, NEW: review.md grammar -> state, status line, exits, summary text)
aidd_review_items.py --> aidd_rules, check_spec (lazy, optional)      never imports aidd_review / aidd_review_state
aidd_review_state.py --> stdlib only                                  never imports aidd_review / aidd_review_items
```

Rules of the split: (1) the two new modules do NO file IO and never print; every input arrives as a parameter (texts, bytes, mtimes, dicts) and every output is a return value, so each is tested with plain literals and needs no other new module; (2) `aidd_review.py` reaches them ONLY through `_items()` and `_state()` (lazy loaders built like the 007 `_rules()`: script dir on `sys.path`, `import`, return the module; `ImportError` propagates and every caller fails closed: `review_state` reason `aidd_review_items/aidd_review_state is not importable next to aidd_review.py (reinstall AIDD)`, CLI exit 3), never at import time, so its tests replace both with fakes (`mock.patch.object(aidd_review, '_items', return_value=fake)`); (3) where a value crosses a module boundary its shape is the one written below, nothing else; (4) the compiled `CODE_RE` is owned by `aidd_review_items` and handed to `aidd_review_state` as the `code_re` parameter (state never compiles its own copy; its tests compile the literal of "Code grammar" below).

**Code grammar (one definition, Python and page JS carry the same strings)** (amended: `API`/`COMP`/`CTL`/`SCREEN` take 1 to 5 digits, `FR`/`AC`/`T` 1 to 4)

```
CODE_RE         ^(SUMMARY|Q\d{1,3}|D\d{1,3}(?:-?[a-z])?|V-\d{1,3}|(?:FR|AC|T)-\d{1,4}(?:-?[a-z])?|(?:API|COMP|CTL|SCREEN)-\d{1,5}(?:-?[a-z])?)$
GENERIC_CODE_RE ^(FR|AC|API|T|SCREEN|COMP|CTL|V)-\S+
PLACEHOLDER_RE  ^[A-Z]+-[nNxX]+(?:-F[nNxX]+)?$     (FR-nnn, COMP-nnn, SCREEN-XX, SCREEN-XX-Fnn; anchored: AC-01-n, FR-004-x are NOT placeholders)
FIELD_ROW_RE    ^(?:SCREEN|COMP)-\d+-F\d+$         (SCREEN-<nn>-F<nn>: field rows of a screen, not items)
```

Python: every pattern is `re.compile(..., re.ASCII)` and used with `.fullmatch(token)` (so `FR-٣` with a Unicode digit and `FR-1` plus a trailing newline are rejected); the JS copy uses the same source string with `RegExp(CODE_RE_SRC).test(token)` (JS `\d` is ASCII and `$` without the `m` flag does not accept a trailing newline). A shared candidate list (`FR-004b`, `AC-01-n`, `V-5`, `D24b`, `FR-4.1`, `FR-٣`, `FR-1\n`, `FR-301"><img`) is asserted to give identical results in both (T-02 parity test; T-01 asserts the Python side in `tests/test_aidd_review_items.py`).

## Pre-build and closing audits for this spec

No separate pre-build subagent: the human approval of the review of this spec is the gate (R5 advisory by default). ONE closing auditor in wave 3 (T-05), first line `CLOSING AUDIT [domains: security, functional, performance] [tasks:<h8>] [verify:<v8>]`, never haiku. Security checklist: `--wait` writes nothing and records no consent; `--check`/`--wait` print one status line and never file contents, and the docs tell agents never to read review.md/review.html (FR-309); review.md alone approves nothing; escaping and CSP hash of both templates; the picked-folder validation (spec AND tasks_hash of the picked `review.html`); carry-over never writes `review.md` and never carries a changed, new or re-added code; legacy file never crashes; an over-cap spec cannot be approved by a bare tagged answer; the FR-313 summary route accepts only the exact hook-recorded owner label (`str.strip() == SUMMARY_LABEL`, answers only through `_summary_answer`, no typed fallback) on a question that contains `aprobar`/`approve` and the current tag, never agent-forged text; near-misses (`aprobar con resumen`, `Aprobar con resumem`, `Aprobar con resumen ya`) are refused by EVERY route, including the generic tagged-answer route and its typed fallback (the `APPROVE_LABEL` lookahead in both `aidd_status.py` and `rule_gate.py`), so none approves with `source=answer`; the summary check runs first in both `cmd_approve` branches and before the complete branch of `rule_gate`, and every approval it makes records `source=summary`; the `rule_gate` delegate fails closed when `aidd_status` is not importable; `--summary` writes nothing; `_carry_over` merges `sections` + `digests` correctly and a line without ` @d8` is never carried. Functional: the completeness warnings against the real b1SycLink shapes (F28, F23, F13, F15). Performance: page size and extraction time on `F13-eDoc-Emission-Engine` and an F15-shaped fixture (about 540 coded rows), plus `review_state` cost (it now extracts once per call). Structure: the module split holds (`aidd_review_items` and `aidd_review_state` do no file IO, never print, import neither each other nor `aidd_review`; `aidd_review` reaches them only through `_items()`/`_state()` and fails closed without them), and all three modules are byte-identical in `adapters/dot-aidd/scripts/`.
